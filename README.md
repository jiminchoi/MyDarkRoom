# MyDarkRoom

## 0.7.1: 기하 미리보기 반응성·수동 자동 크롭

- **400만 화소 RAW 미리보기를 유지**하면서 회전·원근·업라이트·크롭도 WebGL2에서 표시합니다. 기하 보정 후 노출/톤커브를 움직일 때 서버 JPEG를 재생성/전송하지 않습니다. 색/마스크 보정 전후 비교도 같은 기하 변환으로 GPU에서 처리합니다. 원본 크기 JPEG 저장과 RAW 현상은 기존 CPU 경로를 사용합니다.
- 슬라이더·톤커브를 드래그하는 동안에는 히스토그램 읽기를 미루고 손을 놓은 뒤 갱신합니다. 곡선/숫자 UI 갱신을 화면 프레임에 합치고 GPU 커브 업로드도 곡선이 바뀔 때만 수행합니다. 히스토그램의 픽셀 집계 해상도를 낮추지는 않았습니다.
- WebGL2를 사용할 수 없는 CPU 모드에서는 불필요한 원본 좌표 미리보기 요청을 줄이고, 변하지 않은 기하 보정 전 이미지를 재사용합니다. GPU 없는 환경에서는 서버 미리보기 갱신 대기가 남을 수 있습니다.
- **크롭·수평·업라이트 → 각도·원근 변경 시 원본 비율 자동 크롭**을 기본으로 켰습니다. 회전/수직 원근/수평 원근 슬라이더를 움직일 때 빈 부분을 제외한 원본 비율의 최대 영역을 계산합니다. 브라우저에서 즉시 계산하며 JPEG 저장에도 같은 영역을 사용합니다. 기존 수동 크롭을 대체하므로 원하는 영역을 유지하려면 이 옵션을 끄세요. 옵션을 끄는 것만으로 현재 크롭을 해제하지는 않으며, 크롭 해제 버튼은 따로 사용할 수 있습니다. 자동 크롭 결과도 실행 취소/다시 실행에 포함됩니다. 안전한 영역이 없으면 해당 슬라이더 변경을 적용하지 않습니다.
- 업데이트 후 첫 실행은 **빛만 펼친 상태**입니다. 이전 버전에서 자동 저장된 전체 펼침 상태는 새 기본값으로 전환하며, 이후 직접 선택한 접힘 상태는 계속 기억합니다.
- 기하 보정 화면에서 100% 및 마스크를 직접 편집하는 방식은 이번 변경에 포함하지 않았습니다. 기존처럼 **원본 좌표 보기 · 마스크 편집**에서 사용합니다. GPU와 CPU의 확대/보간 방법이 달라 날카로운 경계나 미세 그레인은 미리보기와 저장본에서 차이가 날 수 있습니다.


## 0.7.0: 자동 보정과 편집 도구 개선

- **자동 수평 / 자동 수직 / 자동 업라이트**를 분리했습니다. 긴 직선 구간을 검출하고 중복 테두리를 합친 뒤, 선의 방향·화면 내 분포·소실점 지지를 확인합니다. 원근 보정에는 수평과 수직 양쪽의 근거가 필요합니다. 방향이 충돌하거나 과도한 변형/크롭이 필요하면 오류 안내만 표시하고 기존 설정을 유지합니다. 자연물/건물을 의미적으로 인식하는 AI 기능은 아니며, 기준이 부족한 풍경에서는 작동하지 않을 수 있습니다.
- 자동 보정 성공 시 **빈 가장자리를 제외하고 원본 비율을 유지하는 최대 영역으로 자동 크롭**합니다. 변환된 원본과 출력 캔버스 안쪽에 영역을 맞추며, 출력 캔버스 면적의 65% 미만만 남으면 자동 적용을 거부합니다. 0.7.1부터는 수동 각도/원근 변경에도 원본 비율 자동 크롭 옵션을 제공합니다.
- **빛 → 자동 밝기 보정**은 원본 밝기 분포로 노출·대비·하이라이트·그림자를 제한적으로 설정합니다. 채도·색온도·틴트·톤커브·마스크는 유지하고, 실행 취소가 가능합니다. 예술적 의도를 판단하지는 않으므로 야경/역광에서는 결과를 확인하세요.
- 슬라이더 손잡이를 큰 둥근 사각형으로 바꿨습니다. **손잡이 더블 클릭**으로 해당 항목만 초기값에 복원합니다. 그레인 크기는 1, 흑백 채널은 30·59·11 등 각 항목의 기본값을 사용합니다. 좌우 화살표 조절도 유지됩니다.
- 카테고리 제목을 눌러 접고 펼칠 수 있으며 브라우저에 상태를 기억합니다. **프리셋 → 빛 → 색 → 톤커브 → 흑백 채널 믹서 → 색조 → 그레인 → 크롭·수평·업라이트 → 마스크** 순서입니다. 색조에는 색상 띠·선택 색 견본·색 이름을 표시합니다.
- 톤커브의 다섯 슬라이더를 그래프 편집으로 대체했습니다. **클릭: 점 추가 / 드래그: 가로·세로 이동 / 내부 점 더블 클릭: 삭제 / 곡선 초기화**. 최대 32개 제어점을 지원합니다. 다른 제어점 위치를 고정하는 구간별 3차 Hermite 보간으로 연결하며, 선택 점과 인접 구간의 곡선이 바뀝니다. GPU/CPU/원본 JPEG가 동일한 256 샘플 곡선을 사용합니다. 기존 5점 프리셋은 기존 선형 형태로 읽고, 직접 그래프를 편집하면 3차 곡선으로 전환합니다. 새 곡선도 사용자 프리셋 저장/파일 입출력/undo에 포함됩니다.
- 크롭의 **네 변과 네 모서리, 총 8개 핸들**로 크기를 조절합니다. 내부는 이동, 바깥 드래그는 새 영역 선택이며 고정 비율을 유지합니다.
- 데스크톱을 브라우저 높이에 맞추고 도구 패널을 독립 스크롤로 바꿔 하단 페이지 여백을 제거했습니다. 모바일은 세로 페이지 스크롤을 유지합니다. 의존성과 Windows 실행 방법은 바뀌지 않았습니다.


## 0.6.0: 크롭·자동 수평·업라이트

- **크롭 · 수평 · 업라이트 → 크롭 편집**을 켜고 사진을 드래그해 영역을 선택합니다. 선택 영역 안을 드래그하면 위치가 이동합니다. **크롭 적용**으로 결과를 확인합니다.
- 자유/원본/1:1/3:2/4:3/16:9 및 세로 비율을 지원합니다. 비율을 바꾸면 현재 영역 안에 맞춰 중앙 크롭을 만들며, 편집 중 새 영역을 그리면 선택한 비율을 유지합니다. **크롭 해제**는 자르기만, **기하 초기화**는 회전·원근·자동 업라이트까지 초기화합니다.
- **자동 수평**은 원본 현상 이미지에서 주요 수평·수직선의 방향을 분석합니다. **자동 업라이트**는 직선의 소실점으로 원근을 추정합니다. 수직/수평 소실점이 모두 안정적으로 추정되면 양축을, 수직 소실점만 추정되면 수직 원근을 보정합니다. 0.7.0부터는 더 보수적인 신뢰도 기준과 원본 비율 자동 크롭을 사용합니다. 위 최신 안내를 참고하세요.
- **회전 / 수직 원근 / 수평 원근**을 수동으로 미세 조정할 수 있습니다. 자동 버튼은 원본 기준으로 다시 분석해 기존 기하 설정을 대체합니다. 자동 결과는 모든 장면에서 정확하지 않으므로 눈으로 확인하고 필요하면 실행 취소하세요. 자동 보정은 원본 비율로 자동 크롭하며, 수동 변경도 자동 크롭 옵션을 켜서 처리할 수 있습니다. 출력 캔버스를 원본 밖으로 확장하거나 빈 부분을 생성해 채우지는 않습니다.
- 원본에 색/마스크 보정을 적용한 후 기하 변환과 크롭을 수행해 JPEG로 저장합니다. JPEG 장축 크기 선택은 크롭한 결과에 적용합니다. 일반 프리셋은 사진별 크롭을 바꾸지 않으며, 편집 이력은 기하 설정도 포함합니다.
- 기하 보정 화면은 0.7.1부터 WebGL2 기반 화면 맞춤 미리보기이며 GPU를 사용할 수 없으면 CPU 경로를 사용합니다. **원본 좌표 보기 · 마스크 편집**을 켜면 저장한 기하 설정을 유지한 채 기존 원본 100% 확인/마스크 편집을 사용할 수 있습니다. 다시 끄면 결과 화면으로 돌아갑니다. 이 원본 보기 상태에서도 JPEG에는 기하 보정/크롭이 반영됩니다. 기하 화면의 전후 비교는 같은 기하 조건에서 색/마스크 보정 전후를 비교합니다.
- 히스토그램은 보정/크롭한 미리보기 영역을 기준으로 갱신합니다. 사진 교체/새로고침 시 편집 상태 초기화 등 기존 프로젝트 저장 제한은 동일합니다.

자동 분석에 `opencv-python-headless==5.0.0.93`이 추가됐습니다. 새 ZIP을 풀고 `start_windows.cmd`로 시작하면 변경된 의존성을 설치합니다. 별도 OpenCV GUI 설치는 필요 없습니다. EXE 패키징은 아직 진행하지 않았습니다.

## 0.5.2: 원형 그라디언트와 거리별 농도

- **부분 보정 · 마스크 → 원형 그라디언트 → 추가**를 선택하고, 사진 위에서 **중심점→반경 끝점**으로 드래그합니다. 사진 종횡비/화면 배율과 관계없이 원본 픽셀 기준의 원이며, **사진에서 그리기**를 켠 상태에서 다시 드래그하면 중심과 반경을 바꿀 수 있습니다.
- **거리별 농도**에서 0·25·50·75·100% 지점의 농도를 각각 0–100%로 조절합니다. 원형의 거리 0%는 중심, 100%는 테두리입니다. 선형에서는 시작점과 끝점에 해당합니다. 옆 그래프가 실제 농도 변화 모양을 보여줍니다.
- 원형 기본값은 중심 100%→테두리 0%로 부드럽게 줄어듭니다. 중간 농도를 높이면 중간 거리에도 보정을 더 강하게 적용할 수 있습니다. 순서를 뒤집거나 중앙을 비워 링 모양의 영향도를 만들 수도 있습니다. 반전 전 원 바깥은 항상 0%이며, 테두리 농도를 높이면 원 경계가 뚜렷해질 수 있습니다.
- 선형도 같은 5점 농도 설정을 지원합니다. 시작 전과 끝 후에는 각각 양 끝 농도가 유지됩니다. **농도 기본값**은 기존의 부드러운 기본 변화로 되돌리고, 중심/반경·방향과 보정값은 유지합니다. 기존 선형 마스크의 기본 모양은 그대로입니다.
- 반전·불투명도·마스크별 보정, 오버레이, 100% 보기, 히스토그램, JPEG 저장 및 실행 취소/다시 실행에 연결됩니다. 마스크 수는 기존처럼 최대 8개이며 사진별 마스크 영구 저장은 아직 제공하지 않습니다.

예: 원형 마스크의 노출을 낮추고 **반전**하면 바깥을 어둡게 하는 비네팅으로 쓸 수 있습니다. EXE 패키징은 이번 변경에 포함하지 않았습니다.

## 5단계: RAW 호환 로딩·톤 커브·JPEG 저장

### Nikon Z5 II / 고효율 NEF

현재 고정된 rawpy 0.27.1은 최신 배포 버전이지만 공개 LibRaw의 Nikon HE/HE★ 압축에는 제약이 있습니다. 미지원 형식 오류가 발생하면 **Adobe DNG Converter → LibRaw** 순서의 대체 로딩을 사용합니다. 내장 JPEG를 RAW 현상 결과로 대신 사용하는 방식은 아닙니다.

1. Windows에 [최신 Adobe DNG Converter(공식 안내)](https://helpx.adobe.com/camera-raw/using/adobe-dng-converter.html)를 설치하고 앱을 다시 실행합니다. 이 프로그램은 저장소에 포함하지 않습니다.
2. 기본 설치 위치를 자동 탐색합니다. 직접 지정해야 하면 PowerShell에서 `$env:MYDARKROOM_DNG_CONVERTER='C:\Program Files\Adobe\Adobe DNG Converter\Adobe DNG Converter.exe'`를 설정한 뒤 같은 창에서 `.\start_windows.cmd`를 실행합니다.
3. 미지원 NEF를 작업용 폴더의 무손실 압축 DNG로 변환한 뒤 현상합니다. 원본 NEF는 수정하지 않으며 변환 결과는 같은 사진의 확대/저장에 재사용하고 세션 삭제 시 지웁니다.

**현재 검증 한계:** Linux에서는 변환기 호출 인자·오류 처리·변환 결과 캐시를 모의 테스트했습니다. 사용자의 Z5 II HE/HE★ 실파일과 실제 Windows Adobe 변환기는 아직 실행 검증하지 못했습니다. 따라서 최신 Nikon 전체 지원 또는 해당 오류의 완전 해결을 보장하지 않습니다. 변환기 자체가 지원하지 않거나 변환된 DNG도 읽지 못하면 명시적인 오류를 표시합니다.

### 톤 커브와 단축키

0.7.0부터 RGB 마스터 톤 커브는 최대 32점의 그래프 편집과 3차 보간을 사용합니다. 기존 블랙/25%/중간/75%/화이트의 5점 설정은 이전 프리셋 호환용으로 읽습니다. 원래의 직선은 보정 없음입니다. 기존 사용자 프리셋에는 기본 커브가 자동으로 채워지고 새 프리셋/실행 취소/미리보기/마스크 이후 전체 보정/JPEG에 커브가 반영됩니다.

슬라이더를 선택한 뒤 **좌/우 화살표**로 그 슬라이더의 최소 단위만큼 조절합니다. 전체/부분 노출은 0.01 EV, 정수 슬라이더는 1, 불투명도 등은 해당 최소 단위를 사용합니다. 경계값을 넘지 않으며 변경은 실행 취소에 기록됩니다.

### JPEG 저장 창

- **JPEG 저장**을 누르면 저장 창이 열립니다. 파일 이름, 품질(1–100), DPI(1–2400)를 지정합니다. DPI는 인쇄용 메타데이터이며 픽셀 해상도를 바꾸지 않습니다.
- 크기 탭: **원본 / 최소·장축 2000px / 커스텀·장축 1–20000px**. 비율을 유지하고 원본보다 확대하지 않습니다. 전체 현상과 보정 후 Lanczos로 축소하고 sRGB ICC 프로파일을 넣습니다.
- Windows **Chrome/Edge**의 로컬 앱에서는 **저장 폴더 선택**이 브라우저의 실제 폴더 선택 창을 호출합니다. 선택한 폴더에 직접 쓰고 기존 파일과 이름이 겹치면 `(2)` 등 번호를 붙입니다. 브라우저 보안 정책상 선택한 폴더 이름을 표시하며 전체 절대 경로는 읽지 않습니다.
- 폴더 선택 API를 지원하지 않는 브라우저나 폴더 미선택 상태에서는 기존 다운로드 기능을 사용합니다. 다운로드 위치는 브라우저 설정을 따릅니다. 폴더 권한은 해당 브라우저/세션에 필요하며 서버 경로로 대신 저장하지 않습니다.

### 성능/메모리 점검

전체 크기 마스크 처리를 128행씩 수행해 큰 임시 전체 프레임을 줄였습니다. 사진 교체 시 이전 세션/RAW·DNG·디스크 캐시와 GPU 텍스처를 정리하고, 사용이 끝난 메모리 매핑과 ImageBitmap/페이지 종료 Worker·GPU 프로그램도 해제합니다. 브러시 편집 이력은 변경되지 않은 획의 스냅샷을 공유하고, 마스크 보정 요청은 동시에 중복 실행하지 않도록 합칩니다.

26개 테스트와 반복 교체/부분 보정/저장 스트레스 검사를 수행했습니다. **유한한 Linux/Chromium 검증에서 안정화를 확인했으며 모든 Windows 드라이버·파일·장시간 실행에서 누수가 없다는 보장은 아닙니다.** 자세한 수치는 `VALIDATION.md`를 참고하세요. `scripts/browser_stage5_check.py --nef 파일.NEF`로 저장/커브/단축키/리소스 검사를 실행할 수 있고 Linux에서 `--pid 서버PID`를 주면 서버 RSS도 측정합니다.

## 4단계: 마스크별 부분 보정

1. NEF를 열고 **부분 보정 · 마스크**에서 브러시·선형 그라디언트·색상 범위·휘도 범위 중 하나를 선택해 **추가**합니다. 최대 8개를 만들 수 있습니다.
2. 브러시는 사진 위를 드래그해 칠합니다. 크기·경계 부드러움·지우개를 사용할 수 있습니다. 그라디언트는 사진 위에서 시작점→끝점을 드래그합니다(시작 0%, 끝 100%). **사진에서 그리기**를 끄면 100% 확대 화면에서 이동할 수 있습니다.
3. 색상 마스크는 **사진에서 색 찍기**를 누르고 사진을 클릭하거나 색상 선택기를 사용한 뒤 허용 범위·경계 부드러움을 조절합니다. 휘도 마스크는 밝기 하한/상한(0–1)과 경계 부드러움으로 영역을 지정합니다. 영역 선택은 전체 보정 전 카메라 WB 현상 이미지의 sRGB 색상/밝기를 기준으로 합니다. 색상 거리는 RGB 기반입니다.
4. **이 마스크의 보정**에서 노출·대비·하이라이트·그림자·색온도·틴트·채도를 조절합니다. 각 마스크는 고유한 보정값을 가집니다. 이름·사용 여부·반전·불투명도도 바꿀 수 있습니다. 목록의 생성 순서대로 보정을 누적한 뒤 전체 보정을 적용합니다.
5. **선택 영역 표시**로 빨간 오버레이를 켜고 끕니다. 영역 표시는 JPEG나 히스토그램에 들어가지 않으며 실제 부분 보정만 반영됩니다. 누르고 보정 전을 볼 때 영역 표시는 숨겨집니다.
6. 마스크 추가/삭제, 브러시 획/지우개, 그라디언트 재지정과 마스크별 보정도 실행 취소/다시 실행할 수 있습니다. **초기화**는 전체 보정과 마스크를 함께 지웁니다. 일반 프리셋을 적용하면 마스크는 유지합니다. 사용자 프리셋 파일에는 사진별 마스크를 넣지 않습니다.

마스크는 현재 사진의 메모리 편집 상태이며, 새 사진 열기·새로고침 후에는 유지되지 않습니다. 아직 프로젝트/사이드카 저장은 제공하지 않습니다. JPEG로 저장하면 적용 결과가 포함됩니다.

마스크 계산/부분 보정은 CPU에서 수행해 선형 16비트 텍스처로 GPU 미리보기에 올립니다. 마스크를 바꿀 때 짧은 갱신 대기가 있으며, 전체 보정 슬라이더는 기존 GPU 경로를 유지합니다. CPU 대체 모드와 원본 JPEG에서도 같은 마스크 엔진을 사용합니다. 브러시는 원본 비율에 고정된 긴 변 최대 1024px 필드를 사용하므로 확대/저장 시 같은 영역에 매핑되지만 매우 작은 경계는 부드러워질 수 있습니다. 마스크당 최대 64획/2048포인트, 한 획 최대 256포인트이며 긴 획은 입력 중 간소화합니다. 색상/휘도 선택은 축소 RAW 현상과 전체 현상의 미세한 차이에 따라 경계가 달라질 수 있습니다.

실행 중인 앱에서 마스크 기능 검증:

```powershell
.venv\Scripts\python scripts/browser_mask_check.py --nef "C:\Photos\sample.NEF"
```

브라우저 검증 의존성과 설치 방법은 아래 검증 절을 참고하세요. Windows 실행 방식과 Python 3.12 요구사항은 그대로입니다.

**3단계 추가:** 흑백 채널 믹서, 기본/사용자 프리셋, 색조 토닝, 그레인, 실행 취소/다시 실행, 프리셋 파일 저장·불러오기.

### 3단계 사용법

- **흑백 사용**을 켜고 빨강·초록·파랑 비중(0–200)을 조절합니다. 비중은 합계로 정규화해 중립 회색을 유지하며, 세 값이 모두 0이면 표준 밝기 비중을 사용합니다.
- **색조**의 각도(0–360°)와 강도로 전체 사진에 토닝을 적용합니다. 흑백에서도 세피아·청색 등의 톤을 줄 수 있습니다. 기존 색을 회전하는 HSL 조절과는 다른 전체 토닝입니다.
- **그레인**의 양과 크기를 조절합니다. 패턴은 원본 좌표에 고정되어 움직이거나 재현상해도 바뀌지 않습니다. 100%에서 질감을 확인하세요. 축소 미리보기는 샘플링 때문에 최종 JPEG를 축소해 보는 것과 질감이 다를 수 있습니다.
- 프리셋 목록에서 기본 현상·클래식 흑백·부드러운 인물·따뜻한 필름·실버 그레인을 선택합니다. 프리셋은 노출을 포함한 모든 보정값을 바꿉니다.
- 이름을 입력하고 **저장**하면 현재 값을 사용자 프리셋으로 저장합니다(최대 100개). 같은 이름도 별개 항목으로 저장됩니다. **삭제**는 선택한 사용자 프리셋만 삭제합니다.
- 사용자 프리셋은 같은 브라우저·같은 앱 주소에 유지됩니다. 다른 PC/브라우저로 옮기거나 백업할 때 **프리셋 파일 저장**으로 JSON을 내려받고 **파일 불러오기**로 복원하세요. 가져온 첫 프리셋이 적용됩니다. 브라우저 데이터 삭제 시 로컬 저장도 지워집니다.
- **실행 취소 / 다시 실행**, `Ctrl+Z` / `Ctrl+Y` 또는 `Ctrl+Shift+Z`를 사용할 수 있습니다. 슬라이더 한 번의 드래그, 프리셋 적용, 초기화를 각각 한 단계로 기록하며 최대 100개 상태를 유지합니다. 사진을 새로 열면 편집 이력은 시작 상태로 돌아갑니다. 프리셋 저장/삭제는 사진 보정 이력에 포함하지 않습니다.

흑백·토닝·그레인은 WebGL2 미리보기, CPU 대체 모드, 히스토그램, 100% 디테일, JPEG 저장에 적용됩니다. 보정 전 비교에서는 이 효과들을 제외합니다. Windows 실행 파일과 Python 3.12 설치 요구사항은 2단계와 같습니다.

라이트룸보다 가볍고 캐주얼한 개인용 사진 편집 도구. **NEF 열기 → RAW 현상 → 기본 보정 → JPEG 저장**에 더해, **2단계: 400만 화소 GPU 미리보기·히스토그램·100% 확대·전후 비교**를 구현합니다.

### Windows — 기본 사용 환경

1. [Python 공식 사이트](https://www.python.org/downloads/windows/)에서 **Python 3.12 64비트**를 설치합니다. 설치 옵션에서 Python Launcher(`py`)를 포함합니다.
2. 프로젝트 폴더를 압축 해제한 뒤 **`start_windows.cmd`를 더블클릭**합니다.
3. 처음에는 의존성을 설치하므로 인터넷 연결이 필요합니다. 준비되면 기본 브라우저가 자동으로 열립니다. 이후에는 의존성 목록이 바뀌었을 때만 다시 설치합니다.

## 사용법

1. **NEF 열기** 또는 드래그 앤 드롭으로 파일을 선택합니다. 단축키 `O`도 사용할 수 있습니다.
2. 노출(±3 EV), 대비, 하이라이트, 그림자, 색온도, 틴트, 채도를 조절합니다. 색온도/틴트는 카메라 화이트밸런스에 더하는 상대 보정이며 켈빈 값이 아닙니다.
3. **누르고 보정 전 보기**로 카메라 WB 기본 현상 결과와 비교합니다. **초기화**는 모든 보정을 0으로 되돌립니다.
4. **JPEG 저장**을 누르면 원본 해상도로 다시 현상한 `원본이름-edited.jpg`를 브라우저 다운로드로 저장합니다. 품질 95, 4:4:4, sRGB ICC 프로파일을 사용합니다.

### 2단계: 미리보기와 디테일 확인

- **약 400만 화소 미리보기**: 종횡비를 유지하며 최대 4,000,000픽셀로 준비합니다. 작은 원본은 확대하지 않습니다. 16비트 선형 RGB를 WebGL2 텍스처로 올린 뒤 슬라이더 보정을 GPU 셰이더로 처리하므로 매 조작마다 서버에 보정 이미지를 요청하지 않습니다. RAW 디코딩/디모자이킹과 JPEG 저장은 CPU에서 처리합니다.
- **GPU 상태 표시**: 브라우저가 실제 하드웨어 가속을 제공할 때 GPU를 사용합니다. WebGL2가 없거나 초기화/텍스처 업로드에 실패하면 CPU 보정으로 전환합니다. 식별 가능한 소프트웨어 WebGL 렌더러는 별도 표시하며 실제 GPU 성능으로 간주하지 않습니다. Windows Chrome/Edge에서 하드웨어 가속을 켜두세요.
- **RGB 히스토그램**: 보정 후 전체 미리보기 픽셀을 256개 밝기 구간으로 집계합니다. 확대 영역이나 전후 분할 경계에 따라 집계 범위가 바뀌지 않습니다. GPU 보정 결과를 읽고 별도 Worker에서 집계하며, 슬라이더 조작 후 짧은 지연을 두어 갱신합니다. 그래프 세로축은 작은 분포도 보이도록 제곱근 스케일입니다. CPU 대체 모드는 JPEG 미리보기 기준이라 미세한 차이가 생길 수 있습니다.
- **100% 확대**: `100%` 버튼이나 `1` 키를 누릅니다. 처음 한 번은 전체 RAW를 현상하여 임시 디스크 캐시에 저장한 뒤 현재 보이는 영역만 가져옵니다. 원본 1픽셀을 화면의 물리적 1픽셀에 대응시킵니다(Windows 배율/브라우저 DPI 반영). 드래그로 이동하고 `화면 맞춤` 또는 `F`로 돌아갑니다. 사진을 더블클릭하면 해당 위치를 중심으로 확대합니다. 디테일을 불러오는 동안은 축소 미리보기가 표시됩니다.
- **전후 비교**: 버튼을 누르고 있으면 보정 전을 확인합니다. `전후 나눠 보기`를 켜면 왼쪽은 보정 전, 오른쪽은 보정 후이며 경계 슬라이더로 비율을 바꿉니다. 확대/이동 위치가 양쪽에서 일치합니다. 보정 전은 카메라 WB로 기본 현상한 결과입니다.

100% 상세 영역은 요청당 최대 4096×4096픽셀입니다. 이보다 큰 물리적 뷰포트는 현재 상세 영역 바깥에 축소 미리보기가 남을 수 있습니다. 일반적인 1080p/1440p/4K 화면을 대상으로 합니다. 원본 캐시는 최대 한 장만 유지하며 다른 사진의 원본을 현상하면 교체합니다.

원본 NEF는 수정하지 않습니다. 작업용 사본과 미리보기는 임시 세션으로만 보관하며, 서버 종료 시 삭제합니다. 최대 3개 세션을 유지하고 네 번째 사진을 열면 가장 오래 사용하지 않은 세션을 제거합니다. 파일당 최대 256 MB. 사진별 보정값 자동 저장, 카탈로그, 자르기, 일괄 처리는 후속 단계 범위입니다. 원본 촬영 EXIF/GPS는 JPEG에 복사하지 않습니다.

## RAW 처리와 지원 범위

- rawpy **0.27.1** / LibRaw **0.22.1**. 지원 범위는 해당 엔진의 카메라 및 압축 형식 지원에 따릅니다. **최신 니콘 NEF 전체 지원을 보장하지 않습니다.** 특히 기종별 High Efficiency / High Efficiency★ 파일은 실제 파일로 별도 확인해야 합니다. 지원하지 않는 파일은 명시적인 오류를 표시합니다.
- 최초 열기: 카메라 WB, 자동 밝기 보정 없음, 16비트 선형 sRGB, 최대 400만 화소 캐시. 원본이 1600만 화소 이상일 때 half-size 현상을 사용하고 그보다 작으면 전체 현상 후 축소합니다. 슬라이더 조작 시 RAW를 재현상하지 않습니다.
- 저장: AHD 디모자이킹으로 원본 해상도 재현상 후 동일한 보정 파이프라인 적용. NEF 내 방향을 반영합니다. 축소 현상과 전체 현상의 미세한 디테일은 다를 수 있습니다.
- 노출과 WB는 선형 공간에서 적용하고, 톤/채도는 sRGB 변환과 함께 처리합니다. 심하게 과다 노출되어 이미 클리핑된 센서 정보는 복구할 수 없습니다. Nikon Picture Control과 동일한 색 재현을 목표로 하지는 않습니다.
- LibRaw 작업을 직렬화해 중복 현상으로 인한 메모리 폭증을 줄이며, 보정은 작은 스트립 단위로 처리합니다. 큰 RAW의 전체 해상도 현상에는 수백 MB 이상의 RAM이 필요할 수 있습니다.

실제 사용 기종의 무손실 압축 / 비압축 / 고효율 샘플로 지원 여부를 확인한 뒤 범위를 확장할 예정입니다. 주 사용 환경은 Windows이며, 현재 검증 환경은 Linux x86_64 / Python 3.12입니다.

## 검증

`requirements.lock`은 개발/테스트 도구를 포함한 고정 버전 목록입니다.

```sh
.venv/bin/python -m pytest -q
# 실제 NEF 업로드 → 보정 → 원본 크기 JPEG 생성까지 포함
MYDARKROOM_TEST_NEF=/absolute/path/photo.NEF .venv/bin/python -m pytest -q
```

실제 NEF 경로를 지정하지 않으면 실파일 테스트는 **skip**됩니다. 외부 샘플이나 개인 사진은 저장소에 포함하지 않습니다. 모듈 구조는 `darkroom/imaging.py`(현상/보정), `darkroom/app.py`(로컬 API/세션), `darkroom/static/`(UI)입니다.

별도 브라우저 검증(앱이 실행 중이어야 함):

```powershell
.venv\Scripts\python -m pip install -r requirements-browser.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python scripts/browser_check.py --nef "C:\Photos\sample.NEF"
```

`--chromium`으로 기존 Chromium 실행 파일을 지정할 수 있습니다. CI에서만 사용하는 `--software-gl`은 소프트웨어 WebGL 검증이며 실제 하드웨어 가속 검증을 대체하지 않습니다. 테스트는 GPU/CPU 수치 일치, RGB 집계, 약 400만 화소 업로드, GPU 조작 시 서버 미리보기 재요청 없음, 100% 디테일/드래그, 전후 비교, JPEG 다운로드와 CPU 대체 모드를 확인합니다.
