# MyDarkRoom

**3단계 추가:** 흑백 채널 믹서, 기본/사용자 프리셋, 색조 토닝, 그레인, 실행 취소/다시 실행, 프리셋 파일 저장·불러오기.

### 3단계 사용법

- **흑백 사용**을 켜고 빨강·초록·파랑 비중(0–200)을 조절합니다. 비중은 합계로 정규화해 중립 회색을 유지하며, 세 값이 모두 0이면 표준 밝기 비중을 사용합니다.
- **색조**의 각도(0–360°)와 강도로 전체 사진에 토닝을 적용합니다. 흑백에서도 세피아·청색 등의 톤을 줄 수 있습니다. 기존 색을 회전하는 HSL 조절과는 다른 전체 토닝입니다.
- **그레인**의 양과 크기를 조절합니다. 패턴은 원본 좌표에 고정되어 움직이거나 재현상해도 바뀌지 않습니다. 100%에서 질감을 확인하세요. 축소 미리보기는 샘플링 때문에 최종 JPEG를 축소해 보는 것과 질감이 다를 수 있습니다.
- 프리셋 목록에서 기본 현상·클래식 흑백·부드러운 인물·따뜻한 필름·실버 그레인을 선택합니다. 프리셋은 노출을 포함한 모든 보정값을 바꿉니다.
- 이름을 입력하고 **저장**하면 현재 값을 사용자 프리셋으로 저장합니다(최대 100개). 같은 이름도 별개 항목으로 저장됩니다. **삭제**는 선택한 사용자 프리셋만 삭제합니다.
- 사용자 프리셋은 같은 브라우저·같은 앱 주소에 유지됩니다. 다른 PC/브라우저로 옮기거나 백업할 때 **프리셋 파일 저장**으로 JSON을 내려받고 **파일 불러오기**로 복원하세요. 가져온 첫 프리셋이 적용됩니다. 브라우저 데이터 삭제 시 로컬 저장도 지워집니다.
- **실행 취소 / 다시 실행**, `Ctrl+Z` / `Ctrl+Y` 또는 `Ctrl+Shift+Z`를 사용할 수 있습니다. 슬라이더 한 번의 드래그, 프리셋 적용, 초기화를 각각 한 단계로 기록하며 최대 100개 상태를 유지합니다. 사진을 새로 열면 편집 이력은 시작 상태로 돌아갑니다. 프리셋 저장/삭제는 사진 보정 이력에 포함하지 않습니다.

흑백·토닝·그레인은 WebGL2 미리보기, CPU 대체 모드, 히스토그램, 100% 디테일, JPEG 저장에 적용됩니다. 보정 전 비교에서는 이 효과들을 제외합니다. Windows 실행 파일과 Python 3.12 설치 요구사항은 2단계와 같습니다.

라이트룸보다 가볍고 캐주얼한 개인용 사진 편집 도구. **NEF 열기 → RAW 현상 → 기본 보정 → JPEG 저장**에 더해, **2단계: 400만 화소 GPU 미리보기·히스토그램·100% 확대·전후 비교**를 구현합니다.

## 실행

Python **3.12** 권장. Python 서버와 로컬 브라우저로 실행되며, 별도의 클라우드 계정이나 API 키가 필요하지 않습니다. 사진은 실행 중인 컴퓨터에서만 처리합니다.

### Windows — 기본 사용 환경

1. [Python 공식 사이트](https://www.python.org/downloads/windows/)에서 **Python 3.12 64비트**를 설치합니다. 설치 옵션에서 Python Launcher(`py`)를 포함합니다.
2. 프로젝트 폴더를 압축 해제한 뒤 **`start_windows.cmd`를 더블클릭**합니다.
3. 처음에는 의존성을 설치하므로 인터넷 연결이 필요합니다. 준비되면 기본 브라우저가 자동으로 열립니다. 이후에는 의존성 목록이 바뀌었을 때만 다시 설치합니다.
4. 편집하는 동안 콘솔 창을 열어 두고, 종료할 때 `Ctrl+C`를 누릅니다. 기본 JPEG 저장 위치는 브라우저의 다운로드 설정을 따릅니다.

아직 독립 실행형 `.exe`는 아니며 Python 설치가 필요합니다. Windows 실행 파일은 제공하지만 실제 Windows 머신에서의 검증은 남아 있습니다. 문제가 생기면 창에 표시된 오류를 확인하세요.

수동으로 실행하려면 PowerShell에서 다음을 사용합니다.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.lock
.venv\Scripts\python run.py --open-browser
```

### macOS / Linux

```sh
python -m venv .venv
# macOS / Linux
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python run.py
```

터미널에 표시되는 로컬 주소를 브라우저에서 엽니다(기본 포트 8765). 종료는 `Ctrl+C`. `python run.py --port 8766`으로 포트를 바꿀 수 있습니다. 서버는 기본적으로 루프백에만 바인딩합니다. 클라우드에서 실행할 경우 사진은 클라우드 머신으로 업로드되며, 이 버전은 인터넷 공개용 서버가 아닙니다.

## 사용법

1. **NEF 열기** 또는 드래그 앤 드롭으로 파일을 선택합니다. 단축키 `O`도 사용할 수 있습니다.
2. 노출(±3 EV), 대비, 하이라이트, 그림자, 색온도, 틴트, 채도를 조절합니다. 색온도/틴트는 카메라 화이트밸런스에 더하는 상대 보정이며 켈빈 값이 아닙니다.
3. **누르고 보정 전 보기**로 카메라 WB 기본 현상 결과와 비교합니다. **초기화**는 모든 보정을 0으로 되돌립니다.
4. **JPEG 저장**을 누르면 원본 해상도로 다시 현상한 `원본이름-edited.jpg`를 브라우저 다운로드로 저장합니다. 품질 95, 4:4:4, sRGB ICC 프로파일을 사용합니다.

### 2단계: 미리보기와 디테일 확인

- **약 400만 화소 미리보기**: 종횡비를 유지하며 최대 4,000,000픽셀로 준비합니다. 작은 원본은 확대하지 않습니다. 16비트 선형 RGB를 WebGL2 텍스처로 올린 뒤 슬라이더 보정을 GPU 셰이더로 처리하므로 매 조작마다 서버에 보정 이미지를 요청하지 않습니다. RAW 디코딩/디모자이킹과 JPEG 저장은 CPU에서 처리합니다.
- **GPU 상태 표시**: 브라우저가 실제 하드웨어 가속을 제공할 때 GPU를 사용합니다. WebGL2가 없거나 초기화/텍스처 업로드에 실패하면 CPU 보정으로 전환합니다. 식별 가능한 소프트웨어 WebGL 렌더러는 별도 표시하며 실제 GPU 성능으로 간주하지 않습니다. Windows Chrome/Edge에서 하드웨어 가속을 켜두세요.
- **RGB 히스토그램**: 보정 후 전체 미리보기 픽셀을 256개 밝기 구간으로 집계합니다. 확대 영역이나 전후 분할 경계에 따라 집계 범위가 바뀌지 않습니다. GPU 보정 결과를 읽고 별도 Worker에서 집계하며, 슬라이더 조작 후 짧은 지연을 두어 갱신합니다. 그래프 세로축은 작은 분포도 보이도록 제곱근 스케일입니다. CPU 대체 모드는 JPEG 미리보기 기준이라 미세한 차이가 생길 수 있습니다.
- **100% 확대**: `100%` 버튼이나 `1` 키를 누릅니다. 처음 한 번은 전체 RAW를 현상하여 임시 디스크 캐시에 저장한 뒤 현재 보이는 영역만 가져옵니다. 원본 1픽셀을 화면의 물리적 1픽셀에 대응시킵니다(Windows 배율/브라우저 DPI 반영). 드래그로 이동하고 `화면 맞춤` 또는 `F`로 돌아갑니다. 사진을 더블클릭하면 해당 위치를 중심으로 확대합니다. 디테일을 불러오는 동안은 축소 미리보기가 표시됩니다.
- **전후 비교**: 버튼을 누르고 있으면 보정 전을 확인합니다. `전후 나눠 보기`를 켜면 왼쪽은 보정 전, 오른쪽은 보정 후이며 경계 슬라이더로 비율을 바꿉니다. 확대/이동 위치가 양쪽에서 일치합니다. 보정 전은 카메라 WB로 기본 현상한 결과입니다.

100% 상세 영역은 요청당 최대 4096×4096픽셀입니다. 이보다 큰 물리적 뷰포트는 현재 상세 영역 바깥에 축소 미리보기가 남을 수 있습니다. 일반적인 1080p/1440p/4K 화면을 대상으로 합니다. 원본 캐시는 최대 한 장만 유지하며 다른 사진의 원본을 현상하면 교체합니다.

원본 NEF는 수정하지 않습니다. 작업용 사본과 미리보기는 임시 세션으로만 보관하며, 서버 종료 시 삭제합니다. 최대 3개 세션을 유지하고 네 번째 사진을 열면 가장 오래 사용하지 않은 세션을 제거합니다. 파일당 최대 256 MB. 사진별 보정값 자동 저장, 카탈로그, 자르기, 일괄 처리는 후속 단계 범위입니다. 원본 촬영 EXIF/GPS는 JPEG에 복사하지 않습니다.

## RAW 처리와 지원 범위

- rawpy **0.27.1** / LibRaw **0.22.1**. 지원 범위는 해당 엔진의 카메라 및 압축 형식 지원에 따릅니다. **최신 니콘 NEF 전체 지원을 보장하지 않습니다.** 특히 기종별 High Efficiency / High Efficiency★ 파일은 실제 파일로 별도 확인해야 합니다. 지원하지 않는 파일은 명시적인 오류를 표시합니다.
- 최초 열기: 카메라 WB, 자동 밝기 보정 없음, 16비트 선형 sRGB, 최대 400만 화소 캐시. 원본이 1600만 화소 이상일 때 half-size 현상을 사용하고 그보다 작으면 전체 현상 후 축소합니다. 슬라이더 조작 시 RAW를 재현상하지 않습니다.
- 저장: AHD 디모자이킹으로 원본 해상도 재현상 후 동일한 보정 파이프라인 적용. NEF 내 방향을 반영합니다. 축소 현상과 전체 현상의 미세한 디테일은 다를 수 있습니다.
- 노출과 WB는 선형 공간에서 적용하고, 톤/채도는 sRGB 변환과 함께 처리합니다. 심하게 과다 노출되어 이미 클리핑된 센서 정보는 복구할 수 없습니다. Nikon Picture Control과 동일한 색 재현을 목표로 하지는 않습니다.
- LibRaw 작업을 직렬화해 중복 현상으로 인한 메모리 폭증을 줄이며, 보정은 작은 스트립 단위로 처리합니다. 큰 RAW의 전체 해상도 현상에는 수백 MB 이상의 RAM이 필요할 수 있습니다.

실제 사용 기종의 무손실 압축 / 비압축 / 고효율 샘플로 지원 여부를 확인한 뒤 범위를 확장할 예정입니다. 주 사용 환경은 Windows이며, 현재 검증 환경은 Linux x86_64 / Python 3.12입니다.

## 검증

`requirements.lock`은 개발/테스트 도구를 포함한 고정 버전 목록입니다.

```sh
.venv/bin/python -m pytest -q
# 실제 NEF 업로드 → 보정 → 원본 크기 JPEG 생성까지 포함
MYDARKROOM_TEST_NEF=/absolute/path/photo.NEF .venv/bin/python -m pytest -q
```

실제 NEF 경로를 지정하지 않으면 실파일 테스트는 **skip**됩니다. 외부 샘플이나 개인 사진은 저장소에 포함하지 않습니다. 모듈 구조는 `darkroom/imaging.py`(현상/보정), `darkroom/app.py`(로컬 API/세션), `darkroom/static/`(UI)입니다.

별도 브라우저 검증(앱이 실행 중이어야 함):

```powershell
.venv\Scripts\python -m pip install -r requirements-browser.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python scripts/browser_check.py --nef "C:\Photos\sample.NEF"
```

`--chromium`으로 기존 Chromium 실행 파일을 지정할 수 있습니다. CI에서만 사용하는 `--software-gl`은 소프트웨어 WebGL 검증이며 실제 하드웨어 가속 검증을 대체하지 않습니다. 테스트는 GPU/CPU 수치 일치, RGB 집계, 약 400만 화소 업로드, GPU 조작 시 서버 미리보기 재요청 없음, 100% 디테일/드래그, 전후 비교, JPEG 다운로드와 CPU 대체 모드를 확인합니다.
